# ohda-manager

نظام ويب عربي لإدارة العُهَد واللوازم، مصمم للعمل أولاً على كمبيوتر ويندوز بقاعدة بيانات SQLite، مع إمكانية الدخول إليه من الهاتف على نفس الشبكة المحلية، ثم نقله لاحقاً إلى سيرفر/VPS.

## التقنية

- Next.js
- React
- Tailwind CSS
- Prisma ORM
- SQLite
- ExcelJS لاستيراد ملف العهدة الحالي من Excel

## ما تم تنفيذه

- إدارة المواد والوحدات وأرقام صفحات الدفتر القديم.
- عرض الرصيد الحالي لكل مادة ومكان وجودها اعتماداً على سجل الحركات، وليس على رقم مخزن يدوياً.
- المواقع والغرف والموظفون وربط الموظف بموقعه مع حفظ تاريخ تغيّر الموقع.
- سندات إدخال اللوازم وإخراج اللوازم متعددة المواد، مع المسودة والمراجعة ثم الاعتماد.
- بيانات مستند الإدخال: المورد، الفاتورة، تاريخها، لجنة الاستلام، مرجع التقرير، أمر الشراء، السعر الإفرادي والقيمة.
- سند العهدة الشخصية من محتويات غرفة الموظف، مع منع تكرار عهدة كمية سبق ربطها بموظف.
- طباعة سند العهدة على صفحة أو عدة صفحات من دون تحويل الصفحات إلى سندات مستقلة.
- قالب سند العهدة قابل للتعديل وله إصدارات؛ السند القديم يبقى على الإصدار الذي استُخدم له.
- جرد افتتاحي للمواد القديمة التي لا يوجد لها سند إدخال.
- تسجيل سندات إدخال وإخراج تاريخية من الدفتر القديم بوضع مرجعي لا يغيّر الرصيد الحالي.
- ربط جزء من رصيد البداية بسند إدخال تاريخي عند اكتشاف مصدره لاحقاً، من دون مضاعفة الرصيد.
- استيراد Excel الخاص بمركز الرمثا مع الاحتفاظ بالرصد الدفتري والموجود الفعلي والتوزيع على الغرف.
- سجل حركة لكل مادة وإظهار أماكن وجودها الحالية.
- نسخ احتياطية متسقة من SQLite أثناء التشغيل باستخدام `VACUUM INTO`.
- اختبارات آلية عبر GitHub Actions تشمل قاعدة البيانات، استيراد Excel، ترحيل الحركات، النسخ الاحتياطي وبناء Next.js.

راجع `docs/DATABASE_DESIGN.md` للتصميم التفصيلي.

## حماية البيانات

المستودع عام، لذلك لا يجب رفع ملفات العهدة أو قاعدة البيانات الفعلية إليه. الملفات التالية مستثناة من Git:

- `private-data/`
- ملفات Excel/CSV
- ملفات SQLite
- ملفات البيئة `.env`

## الإعداد على كمبيوتر ويندوز

بعد تنزيل المشروع، يمكن تشغيل إعداد كامل من PowerShell من داخل مجلد المشروع:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows-setup.ps1
```

إذا كان ملف الرمثا موجوداً في:

```text
private-data\عهدة الرمثا 2025.xlsx
```

يمكن إنشاء القاعدة واستيراده مباشرة أثناء الإعداد:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows-setup.ps1 -ImportRamtha
```

السكربت يقوم بتجهيز `.env`، تثبيت الحزم، إنشاء SQLite، توليد Prisma، استيراد الملف عند الطلب، ثم بناء نسخة التشغيل.

بعد الإعداد يكفي تشغيل:

```text
start-ohda.cmd
```

وسيظهر عنوان الاستخدام على الكمبيوتر وعنوان الشبكة المحلية الذي يفتح من الهاتف.

## استيراد عهدة الرمثا من Excel

تاريخ الجرد الافتتاحي المعتمد لبيانات ملف **عهدة الرمثا 2025.xlsx** هو:

```text
31/12/2025
```

ويمكن الاستيراد منفرداً بالأمر:

```bash
npm run import:ramtha -- "private-data/عهدة الرمثا 2025.xlsx" --date=2025-12-31
```

هذا التاريخ هو نقطة البداية الرسمية للمخزون في النظام. أي مستندات قديمة أقدم من هذه النقطة يمكن إدخالها لاحقاً كمستندات تاريخية `REFERENCE_ONLY`، وربط سندات الإدخال بما تبقى من رصيد البداية من دون إضافة الكمية مرة أخرى.

المستورد لا يفترض أن الرصيد الدفتري يساوي الموجود، ولا يسقط الصفوف الناقصة. أي اختلاف أو رقم مادة مفقود يحفظ كتحذير للمراجعة.

## الدخول من الهاتف على الشبكة المحلية

نسخة التشغيل تستخدم:

```bash
npm run start:lan
```

ويستمع التطبيق على جميع واجهات الشبكة. مثلاً إذا كان عنوان الكمبيوتر `192.168.1.50` يفتح الهاتف:

```text
http://192.168.1.50:3000
```

الهاتف لا يملك قاعدة منفصلة؛ جميع الأجهزة تستخدم SQLite الموجودة على كمبيوتر ويندوز.

## النسخ الاحتياطي

يمكن الضغط على:

```text
backup-ohda.cmd
```

أو تشغيل:

```bash
npm run backup:db
```

وتحفظ نسخة متسقة داخل `private-data/backups/`. هذا المجلد خاص ومستثنى من GitHub.
