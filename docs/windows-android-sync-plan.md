# خطة تحويل نظام العهدة إلى Windows + Android مع مزامنة

## القرار المعماري

النسخة الحالية Electron + Next.js مفيدة للانتقال، لكنها تشغل خادم Next محلياً داخل برنامج Windows. هذا ليس الشكل النهائي المطلوب.

الشكل النهائي المستهدف:

- تطبيق Windows حقيقي مبني بـ Tauri 2 + React.
- تطبيق Android من نفس واجهة React عبر Tauri 2 Mobile.
- SQLite محلي على كل جهاز للعمل السريع وحفظ المسودات دون اتصال.
- خدمة مزامنة مركزية صغيرة على الـ VPS عبر HTTPS.
- PostgreSQL مركزي هو مصدر الحقيقة للبيانات المشتركة.
- لا يحتاج كمبيوتر Windows إلى تشغيل خادم ويب محلي في الخلفية.
- لا يحتاج Android إلى الاتصال بعنوان IP للكمبيوتر.

## قاعدة مهمة للمخزون

أرصدة المواد لا تتم مزامنتها بطريقة Last Write Wins.

الحركات المعتمدة (إدخال، إخراج، نقل، عهدة، إرجاع، تسوية) تظل append-only، واعتماد أي حركة يتم مركزياً داخل transaction واحدة. بهذه الطريقة لا يستطيع Windows وAndroid خصم نفس القطعة مرتين بسبب العمل المتزامن.

## ما يعمل دون اتصال

يمكن دون اتصال:
- البحث في آخر نسخة متزامنة من المواد والموظفين والغرف.
- إعداد مسودة جرد.
- إعداد مسودة عهدة أو إرجاع.
- حفظ ملاحظات وكميات غير معتمدة.

يتطلب الاتصال:
- اعتماد حركة تغير الرصيد.
- اعتماد سند عهدة أو إرجاع نهائي.
- حل تعارض ناتج عن تغير الرصيد على جهاز آخر.

## المزامنة

كل سجل قابل للمزامنة يحتاج:
- id عالمي UUID/CUID ثابت.
- version رقمي.
- updatedAt.
- deletedAt للحذف المنطقي عند الحاجة.
- deviceId وsyncState محلياً للمسودات.

كل جهاز يحتفظ:
- inbox: آخر تغييرات استلمها.
- outbox: المسودات/التغييرات التي لم ترسل بعد.
- lastSyncCursor.

الخادم يعيد التغييرات منذ cursor السابق، ويقبل العمليات idempotently حتى لا تتكرر الحركة لو أعيد الإرسال بعد انقطاع الشبكة.

## مراحل التنفيذ

1. تثبيت تجربة Windows الحالية وإزالة أخطاء الصفحات التقنية.
2. جعل الواجهة مبنية حول المهام: جرد، تسليم عهدة، إرجاع عهدة، مادة.
3. فصل منطق الأعمال والمخزون عن صفحات Next.js إلى طبقة domain مشتركة.
4. إضافة API مركزي وPostgreSQL على VPS في stack منفصل.
5. إضافة معرفات/version وسجل مزامنة مع ترحيل قاعدة SQLite الحالية دون فقد بيانات.
6. بناء عميل Tauri Windows وتشغيله دون Next server محلي.
7. بناء Android APK من نفس الواجهة.
8. اختبار المزامنة: Windows→Android، Android→Windows، انقطاع الشبكة، إعادة الإرسال، وتعارض الرصيد.
9. بعد نجاح الاختبارات فقط تصبح القاعدة المركزية هي مصدر الحقيقة.

## شرط الترحيل

قبل نقل أي بيانات:
- نسخة احتياطية SQLite.
- مقارنة counts لكل جدول.
- مقارنة مجموع أرصدة كل مادة وكل غرفة وكل موظف قبل/بعد.
- عدم حذف قاعدة Windows القديمة حتى PASS كامل.
